# Redacted protocol-capture contract

## Purpose and boundary

This is the input contract for a later, separately approved live-ingestion plan. It defines what an authorized capture must contain so SABA Socket.IO and IM REST adapters can be designed without guessing. This task performs no site access, authentication, live capture, CAPTCHA work, betting, or secret collection.

The later capture phase is observation-only. It must not access trader-only or staff-only domains, bypass CAPTCHA or anti-bot controls, alter provider state, submit a wager, or probe undocumented endpoints. Authenticated sessions and all live adapters are deferred to that plan. PAPER, ASSISTED, AUTO, bet submission, preflight, receipts, and reconciliation are deferred to an execution plan.

No IP address data is permitted. Provider, client, proxy, forwarded, local, and remote IPv4 or IPv6 values are forbidden, including IPv4-mapped IPv6, scoped IPv6, bracketed addresses, and values under IP-like fields such as `ip`, `ipAddress`, `clientIp`, `remoteIp`, `providerIp`, `remoteAddress`, `forwardedFor`, or `xForwardedFor`. The `source` field is a capture-local label and path template, never a hostname or address.

### Allowed public market data versus forbidden wagering data

The only allowed commercial data is anonymous public market observation: provider event/market/selection identifiers, participants, competition, schedule/live state, public raw odds and odds format, public lines, market/selection status, suspend reason, and settlement rules. These fields describe a market and cannot represent an account action.

All account-specific wagering or transaction data is forbidden, even when redacted values appear harmless: bet, wager, order, ticket, slip, receipt, or history payloads; bet IDs or related identifiers; selections prepared for submission; stake, balance, or limit submissions/results; account-specific prices or limits; bet request/response bodies; acceptance/rejection results; cash-out data; and any account-specific betting payload. No such field may enter the strict schema or a fixture.

## Mandatory capture envelope

Every message is one strict object. Unknown keys are rejected. Required envelope fields are:

| Field | Requirement |
| --- | --- |
| `captureSchemaVersion` | Integer version, initially `1`. |
| `captureId` | New random capture identifier containing no provider/user identity. |
| `provider` / `category` | Exactly `SABA` or `IM`; exactly `FOOTBALL` or `LOL`. |
| `transport` | `SABA_SOCKET_IO` or `IM_REST`. |
| `messageFamily` | One of the families listed below. |
| `direction` | `SERVER_TO_CLIENT`, `CLIENT_TO_SERVER`, or `REQUEST_RESPONSE_PAIR`. |
| `source` | Redacted stable source label, HTTP method and path template or Socket.IO namespace/event; never a full host, credential query, or raw header. |
| `captureStartedAtUtc` / `receivedAtUtc` | ISO-8601 UTC timestamps with millisecond precision. |
| `receivedMonotonicMs` | Nonnegative monotonic arrival time relative to capture start. |
| `connectionOrdinal` | Process-local monotonically increasing positive integer generated by the capture process after redaction. It is never copied, derived, hashed, or encoded from provider, connection-ID, account, or session material. |
| `providerSequence` | Exact provider sequence as string or number, or `null` when absent. |
| `arrivalSequence` | Positive local counter assigned before parsing; never represented as a provider sequence. |
| `sourceTimestampRaw` / `sourceTimestampMs` | Original provider value plus normalized Unix milliseconds, or both `null` when absent. |
| `fullSnapshotId` / `baseSequence` | Baseline identifier and referenced sequence for deltas; `null` only when the family cannot supply them. |
| `payload` | The redacted, family-specific body below. |

Preserve message order exactly. Do not sort, merge, deduplicate, repair gaps, or replace provider time with receipt time. Record duplicates, out-of-order messages, sequence gaps, resets, and reconnect boundaries as observed. If the provider has no sequence, `providerSequence` stays `null`; `arrivalSequence` provides ordering and must be labelled synthetic. Record timestamp units, timezone assumptions, clock domain, and any normalization rule in capture metadata.

`connectionOrdinal` starts at `1` for each capture process and increments on every reconnect or authorized REST context refresh. It is attached only after `redactCapture` has returned. Keys named `session`, `sessionId`, or any punctuation/case/suffix variant remain forbidden and must never be used as a substitute. `SESSION_REFRESH` below is only a `messageFamily` enum value, not a permitted object key.

## SABA Socket.IO families

For both categories, capture the Engine.IO frame type and Socket.IO namespace/event name in addition to the envelope.

### Common SABA payloads

- `BOOTSTRAP_METADATA`: protocol/app version, server time, sport/category IDs and names, competition/league IDs and names, market/type dictionaries, status dictionaries, and initial namespace/channel descriptors.
- `CONNECT`: Engine.IO open parameters (`pingInterval`, `pingTimeout`, allowed upgrades), a local `engineConnectionIdPresent` boolean with the raw Engine.IO identifier omitted, Socket.IO namespace connect/ack, local `connectionOrdinal`, negotiated transport, and first provider sequence/time if supplied.
- `SUBSCRIBE`: namespace, event name, redacted/stable channel label, category and competition filters, subscription action, client arrival sequence, acknowledgement outcome/sequence/time. Never retain the raw session-bearing subscription token.
- `FULL_EVENT_SNAPSHOT`: provider event ID, competition/season/stage, start time, participant IDs/names and provider side order, live flag/state, event scope, full market array, market IDs/types/scopes/lines/settlement/status, and selection IDs/names/status/raw odds/format.
- `ODDS_PATCH`: event, market and selection IDs; changed fields; raw odds and format; line; market/selection status; live state; provider sequence; source time; referenced full snapshot/base sequence.
- `MARKET_SUSPEND`: event/market/selection IDs as applicable, prior and new status, provider reason code, sequence, source time, and baseline reference.
- `HEARTBEAT`: Engine.IO ping/pong or application heartbeat type, direction, provider sequence/time if present, arrival sequence/time, and referenced `connectionOrdinal`. Payload data that is only connection/session material is omitted from the admitted object after in-memory redaction.
- `RECONNECT`: observed close code and non-sensitive reason, last sequence before close, first sequence after reconnect, gap/reset indicator, previous/new connection ordinal, namespace reconnect, resubscribe acknowledgement, and whether a new full snapshot replaced the baseline.

### SABA Football additions

The full snapshot and every affected patch must carry Football sport variant, home/away orientation, regulation/event scope, competition/stage, kickoff, match clock/period/score when live, and supported market identity (`FT_1X2`, `FT_AH`, `FT_TOTAL`, `FH_1X2`, `FH_AH`, `FH_TOTAL`) with exact line and settlement semantics.

### SABA LoL additions

The same families must additionally carry game variant, tournament/stage, series ID, best-of, provider team-side orientation, series score, current map index, map number/scope (`MAP_1` through `MAP_5`), map score, game clock, pause/live state, and market identity (`SERIES_WINNER`, `MAP_WINNER`, `MAP_TOTAL_KILLS`, `MAP_KILL_HANDICAP`, `MAP_DURATION`). A map patch must identify both the series and map; an unscoped map market is invalid.

## IM REST families

Capture request and response as one pair. Retain only HTTP method, path template, non-secret paging/filter values, status code, timing, response revision/ETag if non-secret, and the redacted body. Never retain raw request/response headers, cookies, authorization values, or full URLs.

### IM Football

- `FULL_LIVE_EVENT_LIST`: category/sport ID, list revision, server time, event ID, competition/season/stage, kickoff, home/away IDs/names and order, event scope, live state/period/clock/score, complete market and selection arrays, raw odds/format/status, and page index/size/has-more boundary.
- `EVENT_SELECTION_DELTA`: list revision, base revision/sequence, upsert/remove operation, event/market/selection IDs, every changed field, raw odds/format/status, line, source time, and poll ordinal.
- `MARKET_SUSPEND`: event/market/selection IDs, prior/new status, reason code, revision/sequence, source time, and poll ordinal.
- `PAGINATION_LAZY_LOAD_BOUNDARY`: request page/index/size or redacted cursor-present flag, response item count, has-more flag, first/last event IDs, duplicate/overlap IDs, list revision, and whether scrolling or expansion triggered the request. Cursor values themselves are secret-like opaque state and must be `REDACTED`.
- `SESSION_REFRESH`: trigger (`EXPIRY`, `HTTP_401`, `HTTP_403`, or scheduled), request start/end time, HTTP outcome, previous/new local `connectionOrdinal`, retry relationship, and whether a full-list reset followed. No refresh payload, header, cookie, token, account, member, connection identifier, hostname, or IP value is permitted.

### IM LoL

- `INDEX_MATCH_LIST`: game variant, tournament/stage, series/match ID, team IDs/names and provider side order, best-of, scheduled/live state, series score, current map index, list revision/server time, and pagination boundary.
- `MATCH_DETAILS`: series/match ID, best-of, team orientation, series/map scores, current map index, map scopes, live/pause state, complete market/selection arrays, raw odds/format/status, exact lines/settlement fields, detail revision and source time.
- `REPEAT_POLL`: request start/end, poll ordinal, prior/current revision, not-modified indicator, changed event/market/selection IDs, source time, response status, and next-poll hint. Preserve unchanged responses; do not infer a delta from silence.
- `MARKET_SUSPEND`: series/match, map, market and selection IDs as applicable; prior/new status; reason; revision/sequence; source time; poll ordinal.
- `SESSION_REFRESH`: the same metadata-only contract as IM Football, including the new local `connectionOrdinal` and post-refresh full-details reset indicator.

## Redaction and admission pipeline

Raw protocol data must never be written to the repository, an alternate quarantine directory, a temporary file, a report, or a log. The capture process handles one message in memory and applies this exact order:

1. Pass the provider message through `redactCapture` from `@tool-chenh/adapters` while it exists only in memory.
2. Project only allowed public-market fields, attach capture-local envelope fields including the newly generated `connectionOrdinal`, and strict-parse with the family-specific Zod schema (`z.strictObject` at every object boundary). Do not coerce or silently drop unknown critical fields.
3. Recursively scan every normalized object key and every serialized value using the exact automated rules below. Any single match rejects the entire candidate; there is no allowlist exception for a `REDACTED` value in an admitted file.
4. A human reviewer must inspect the complete candidate and manifest through a non-persisting local review view for identity, IP, credential, and wagering data. The fixture manifest records `reviewed: true`, UTC review time, review-procedure version, and SHA-256 checksum; reviewer identity, usernames, or account data remain outside the capture artifact. Any uncertainty rejects the candidate.
5. Only after redaction, strict validation, automated scan, and manual review all pass may the file be written under `fixtures/captured/<provider>/<category>/`.

The automated scan is mandatory and deterministic:

```text
normalizedKey = key.replace(/[^a-z0-9]/giu, "").toLowerCase()
forbiddenKey = /^(?:.*(?:authorization|cookie|token|password|passwd|secret|apikey|account|member|session).*|auth|sid|host|hostname|(?:client|remote|provider|local|source|proxy|forwarded)?ip(?:address)?|.*ipaddress|remoteaddress|xforwardedfor|forwardedfor|.*bet.*|.*wager.*|order|orderid|orderids|(?:bet|wager|ticket|slip)order.*|.*order(?:submission|result|payload|request|response)|.*ticket.*|.*slip.*|.*receipt.*|.*history.*|stake.*|balance.*|limit.*|.*submission.*|.*result.*)$/u
authorizationValue = /\b(?:Bearer|Basic)\s+[A-Za-z0-9._~+/=-]+/iu
jwtValue = /\beyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\b/u
ipv4Value = /\b(?:(?:25[0-5]|2[0-4]\d|1?\d?\d)\.){3}(?:25[0-5]|2[0-4]\d|1?\d?\d)\b/u
ipv6Candidate = /(?:\[[0-9a-f:.%]+\]|(?<![0-9a-z])[0-9a-f]{0,4}(?::[0-9a-f]{0,4}){2,7}(?:%[0-9a-z_.-]+)?(?![0-9a-z]))/giu
```

Every key is normalized and tested with `forbiddenKey`. The full serialized candidate is tested with `authorizationValue`, `jwtValue`, and `ipv4Value`. Each `ipv6Candidate` is stripped of brackets and any zone suffix, then must be checked with `node:net.isIP`; a return value of `6` rejects it. IPv4-mapped IPv6 candidates are rejected if either the IPv6 validator or nested IPv4 pattern matches. Query-string keys undergo the same normalization. Any scan match is a hard rejection and produces only a fixed diagnostic code and schema-family name.

`redactCapture` recursively replaces the listed secret keys (including punctuation/case variants and suffix forms), redacts matching URL query parameters, and replaces circular references. Redaction is only the first in-memory defense: forbidden keys are omitted during allowed-field projection, and the scanner rejects any that survive. Passing any one gate alone is insufficient.

Forbidden content includes all IPv4/IPv6 and IP-like fields; usernames, account IDs, member codes, email/phone identifiers, passwords, OTP/MFA values, recovery codes, cookies, `Set-Cookie`, session IDs, Socket.IO/Engine.IO connection IDs, access/refresh/ID tokens, JWTs, authorization headers, API/client secrets, browser storage, device fingerprints, proxy credentials, hostnames, full authenticated URLs, raw request/response headers, payment data, and every wagering/transaction item listed above. If safe redaction would remove participant identity needed for event mapping, replace it with a stable capture-local pseudonym and document only the public mapping semantics; never store the original.

On any redaction, schema, scan, or manual-review failure, quarantine is a status only—not a storage location. The raw and rejected payload remains memory-only, emits only a fixed secret-free diagnostic code plus schema-family name, then is immediately securely discarded by dropping references and zeroing mutable buffers where practical. It must never be persisted under `fixtures/captured`, anywhere else in the repository, a quarantine directory, a temporary file, telemetry, console output, test artifacts, or logs. Stop that capture family until reviewed. No captured fixture is evidence that live ingestion or execution is approved.
